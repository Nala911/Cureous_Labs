1. SYSTEM OVERVIEW & PRODUCT ARCHITECTURE
================================================================================
The company manufactures and rents Patient Repositioning Systems (dynamic 
alternating pressure air mattresses for bedridden patients to prevent bedsores).

A finished clinically working system consists of TWO independent physical components:
1. Control Unit (CU) : The electronic pump module containing compressor, valves,
                       micro-controller PCB, and pressure sensors.
2. Overlay (Mattress): The clinical patient surface with polyurethane air cells,
                       antimicrobial cover, and quick-deflate CPR emergency valve.

Clientele:
- Hospitals / Institutions: Bulk rentals (e.g., 5 to 10+ systems per hospital).
- Homecare Patients       : Single system rental.

Rental Commercial Types:
- Pay-Per-Use : Customer is billed based on active patient days in the month
                (from start date to end date).
- Fixed Rental: Flat agreed monthly fee regardless of actual days of usage.
- Clinical Trial/Demo: Temporary zero-cost evaluation period.

Product Tiers (Configured by user in Product Catalog):
- Altern (Basic tier)
- Eturnal One (Premium tier)
- Eturnal One with Foam (Premium tier with safety foam underlay)
- Future models added dynamically by company administrators.

Manufacturing Lot Architecture & Component Progress:
- Devices are manufactured in production runs designated by 'Lot Numbers'.
- A single Lot can manufacture ANY mix of products (Altern4™, Eturnal One™, etc.)
  and both physical components: Control Units (CUs) and Overlays (OVs).
- Individual Control Units and Overlays within the same lot progress through 
  independent manufacturing stages at different paces, but are tracked collectively 
  under that single parent Lot ID.
- Traceability: When a physical device is onboarded by an operator into Asset Master,
  the user assigns the parent lot number from the 'Lots' module.
- Strict Stage-Gating: Devices in assembly/testing cannot be dispatched on rental
  until they complete all manufacturing stages and pass Quality Control certification.

MODULE 1: LOTS (Form Name: Lots, Form Link Name: Lots)
--------------------------------------------------------------------------------
Purpose: Central manufacturing run ledger and batch traceability master.
Governs the production batch lifecycle and provides a live, aggregated 
stage-by-stage ledger of all Control Units and Overlays manufactured under each lot.

Design Principle: Ultra-lean, zero-bloat user experience.
The user enters ONLY ONE FIELD: 'Lot ID'!
All inventory counters and stage breakdowns roll up automatically via 
Asset Master and Quality Control automated workflows.
No unnecessary date pickers, target numbers, supervisors, or manual note fields.

Multi-Product / Mixed Lot Architecture:
A lot does not restrict product models. A single lot (e.g., 26HB04) can contain
Altern4™ CUs, Eturnal One™ CUs, and Overlays simultaneously.

Primary Key:
- Primary Key: `Lot_ID` (Single Line, Mandatory, Unique, Primary Key, Barcode/QR capable).

A. User Interactive Field (The ONLY field user enters):
1. Lot ID                    [Single Line] (Mandatory, Unique, Primary Key, Barcode Scanner enabled)
   - Field Link Name: `Lot_ID`
   - Form Behavior: Visible & Enabled on Add; Locked in Edit mode.

B. Rollup Metrics (Strictly Read-Only, Updated via Asset Master & QC Workflows, Hidden on Add):
*(All metrical rollup fields are completely hidden during record creation to keep the intake form ultra-lean and clutter-free. They are visible in reports and locked in edit mode).*
2. Total CUs Count           [Number - Read Only - Hidden on Add] (Total Control Units registered under this lot)
   - Field Link Name: `Total_CUs_Count`
3. Total Overlays Count      [Number - Read Only - Hidden on Add] (Total Overlays registered under this lot)
   - Field Link Name: `Total_Overlays_Count`
4. Total Units Count         [Number - Read Only - Hidden on Add] (Sum: Total CUs + Total Overlays)
   - Field Link Name: `Total_Units_Count`
5. CUs In Progress           [Number - Read Only - Hidden on Add] (CUs currently in manufacturing/assembly/testing)
   - Field Link Name: `CUs_In_Progress`
6. CUs Rent Ready           [Number - Read Only - Hidden on Add] (CUs that reached "Manufacturing Complete")
   - Field Link Name: `CUs_Rent_Ready`
7. Overlays In Progress     [Number - Read Only - Hidden on Add] (Overlays currently in cutting/welding/testing)
   - Field Link Name: `Overlays_In_Progress`
8. Overlays Rent Ready      [Number - Read Only - Hidden on Add] (Overlays that reached "Manufacturing Complete")
   - Field Link Name: `Overlays_Rent_Ready`

D. Logics & Event Triggers (Functional Specifications in Plain English):

1. On Form Load / On Open Logic:
   - Script File: `scripts/01_lots/1_Lots_onload.deluge`
   - Trigger: User opens `Lots` form to create or view a record.
   - Plain English Logic:
     Step 1: In ADD Mode (`input.ID == null`):
             - Enable only `Lot_ID` for user entry.
             - Hide all 7 metric rollup counters (`Total_CUs_Count`, `Total_Overlays_Count`, `Total_Units_Count`, `CUs_In_Progress`, `CUs_Rent_Ready`, `Overlays_In_Progress`, `Overlays_Rent_Ready`) to keep the intake form ultra-lean.
     Step 2: In EDIT Mode (`input.ID != null`):
             - Lock `Lot_ID` to prevent accidental corruption of downstream hardware traceability.
             - Display and lock all metric rollup counters as read-only.

2. On User Input of Lot ID:
   - No workflow required. Eliminating On User Input eliminates unnecessary client-server
     roundtrips and guarantees instantaneous typing and barcode scanning performance.

3. On Form Validation & Safety Guard (On Validate / Before Submission):
   - Script File: `scripts/01_lots/3_Lots_onvalidate.deluge`
   - Trigger: User clicks Submit on the form.
   - Plain English Logic:
     Step 1: Mandatory check: Ensure `Lot_ID` is not empty.
     Step 2: Sanitize input: Trim leading/trailing whitespace and force uppercase.
     Step 3: Minimum length guard: Ensure `Lot_ID` has at least 3 characters.
     Step 4: Duplicate Lot ID detection:
             - On Add: Query `Lots` form for matching `Lot_ID`. If found, alert user and cancel submission.
             - On Edit: Query for any *other* record sharing this `Lot_ID`. If found, reject and alert.
     Step 5: Default system fields: Default all rollup counters to 0 if null.

4. On Form Submission Success (On Success):
   - Script File: `scripts/01_lots/4_Lots_onsuccess.deluge`
   - Trigger: Record is saved.
   - Plain English Logic:
     Step 1: Redirect cleanly to `All_Lots` report, dismissing the submit loading spinner.

- Control Units (CU) and Overlays (OV) are manufactured, assembled, and stocked COMPLETELY INDEPENDENTLY.

- They are NOT necessarily transported in pairs (e.g. bulk stock transfers of 10 CUs or 5 replacement Overlays).

    - `ALTOV017`  -> Overlay for Altern (#017)

    - `ETOOV064`  -> Overlay for Eturnal One™ (#064)

MODULE 10: RENTAL LOG (Form Name: Rental_Log)
--------------------------------------------------------------------------------
Purpose: Primary commercial and operational billing ledger recording patient usage periods
across all customer bed stations. Captures which physical devices (Control Unit and Overlay
serials), at which customer facility/bed space, for which exact calendar period (Usage Start 
Date to Usage End Date) were deployed, and calculates taxable amounts, 5% GST, and total invoice values.

Commercial Rental Modes Supported:
1. Pay-Per-Use (Daily):
   - Created manually by the operator or via batch generator.
   - Operator selects the 'Bed Station' (via Bed_Station_Title); system auto-fetches the
     linked Rental Agreement, Customer, Product Model, Rental Item, Agreed Daily Rate,
     and currently active Control Unit and Overlay serial numbers.
   - User enters Usage Start Date and Usage End Date.
   - System calculates Number of Days = (Usage End Date - Usage Start Date) + 1 (inclusive).
   - Computes:
     * Taxable Value = (Number of Days * Agreed Rate) - Discount Amount
     * GST (5%)      = Taxable Value * 0.05
     * Invoice Value = Taxable Value + GST
2. Fixed Monthly Rental:
   - Generated on-demand directly from the Rental Agreement row via custom action button
     "[ Generate Monthly Rental Log ]", which opens a stateless confirmation modal.
   - Automatically attaches the agreement's assigned Bed Station and active CU/Overlay serials.
   - Auto-suggests the billing period (Start Date & End Date) from the agreement's monthly cycle
     or the next unbilled cycle, allowing operator review/adjustment.
   - Gated validation: If no Bed Station is currently deployed under the agreement, creation is blocked!
   - Computes:
     * Taxable Value = Agreed Rate - Discount Amount (Fixed full monthly fee, independent of days)
     * GST (5%)      = Taxable Value * 0.05
     * Invoice Value = Taxable Value + GST

Fields:

A. System & Relational Identifiers:
1. Rental Log ID             [Auto-Number] (Primary Key, Syntax: RL-YYYY-XXXX, e.g. RL-2026-0045)
2. Bed Station               [Lookup -> Bed_Stations] (Mandatory; Displays Bed_Station_Title
                             e.g. 'Apollo Hospital - ICU Bed 04 (BST-2026-0042)'.
                             Filtered: In Add mode for Pay-Per-Use, displays active stations.
                             For Fixed Monthly, auto-populated and locked.)
3. Customer                  [Lookup -> Customers - Read Only] (Auto-populated from Bed Station)
4. Rental Agreement          [Lookup -> Rental_Agreement - Read Only] (Auto-populated from Bed Station)
5. Rental Item               [Lookup -> Product_Catalog_Master - Read Only] (Auto-populated from Agreement)
6. Product Model             [Single Line - Read Only] (Auto-populated from Agreement, e.g. Altern4™)
7. Rental Mode               [Single Line - Read Only] (Auto-populated: "Pay Per Use (Daily)" or "Fixed Monthly Rental")

B. Hardware Device Snapshot (Bedside Configuration):
8. Control Unit Serial No    [Single Line - Read Only] (Snapshot of active CU on Bed Station at log creation)
9. Overlay Serial No         [Single Line - Read Only] (Snapshot of active Overlay on Bed Station at log creation)
10. Control Unit Asset       [Lookup -> Asset_Master - Read Only] (Direct link to active CU asset record)
11. Overlay Asset            [Lookup -> Asset_Master - Read Only] (Direct link to active Overlay asset record)

C. Billing Period & Duration:
12. Billing Month            [Single Line - Read Only] (Auto-derived from Start Date, e.g. "October 2026")
13. Usage Start Date         [Date] (Mandatory; Inclusive first day of patient treatment or billing period)
14. Usage End Date           [Date] (Mandatory; Inclusive last day of patient treatment or billing period)
15. Number of Days           [Number - Read Only] (Calculated: (Usage_End_Date - Usage_Start_Date) + 1.
                             For Fixed Monthly, displays actual calendar days for audit transparency while calculation uses fixed fee)

D. Commercial Computations & Taxes:
16. Agreed Rate              [Currency] (Auto-populated from Rental_Agreement.Agreed_Rate. 
                             Daily rate for Pay-Per-Use; monthly rate for Fixed Monthly.
                             Editable by authorized billing users if custom adjustment negotiated)
17. Discount Amount          [Currency] (Default: 0.00; Negotiated concession or credit adjustment)
18. Taxable Value            [Currency - Read Only] (Calculated taxable base amount:
                             Pay-Per-Use  : (Number_of_Days * Agreed_Rate) - Discount_Amount
                             Fixed Monthly: Agreed_Rate - Discount_Amount)
19. GST Rate (%)             [Decimal / Percent - Read Only] (Fixed at 5.00%)
20. GST Amount               [Currency - Read Only] (Calculated: Taxable_Value * 0.05)

24. Zoho Books Invoice No    [Single Line - Read Only] (e.g. INV-2026-00341)
25. Invoice Date             [Date - Read Only] (Date invoice was created in Zoho Books)
26. Invoice URL              [URL - Read Only] (Direct deep-link to view invoice in Zoho Books)
27. Billing Notes            [Multi-Line] (Clinical remarks, patient discharge info, or billing explanations)

void fn_generate_fixed_monthly_rental_log(int agreementId, date startDate, date endDate, decimal discount, string notes)
{
    agrRec = Rental_Agreement[ID == agreementId];
    
    // Safety check: Bed Station must exist
    activeStation = Bed_Station[
        Rental_Agreement == agreementId && 
        Deployment_Status in {"Active on Patient Bed", "Standby at Customer Site"}
    ];
    
    if(activeStation.count() == 0)
    {
        alert "Cannot generate Rental Log: No active Bed Station found for this agreement!";
        return;
    }
    
    stationRec = activeStation.get(0);
    rate = agrRec.Agreed_Rate;
    taxable = rate - ifNull(discount, 0.0);
    if(taxable < 0.0)
    {
        taxable = 0.0;
    }
    gstAmt = (taxable * 0.05).round(2);
    invoiceVal = taxable + gstAmt;
    daysCount = (endDate.daysBetween(startDate)) + 1;
    monthStr = startDate.toString("MMMM yyyy");
    
    // Insert permanent Rental_Log record
    newLog = insert into Rental_Log
    [
        Bed_Station = stationRec.ID,
        Customer = agrRec.Customer,
        Rental_Agreement = agrRec.ID,
        Rental_Item = agrRec.Rental_Item,
        Product_Model = agrRec.Product_Model,
        Rental_Mode = "Fixed Monthly Rental",
        Control_Unit_Serial_No = stationRec.Control_Unit_Serial_No,
        Overlay_Serial_No = stationRec.Overlay_Serial_No,
        Control_Unit_Asset = stationRec.Current_Control_Unit_Asset,
        Overlay_Asset = stationRec.Current_Overlay_Asset,
        Billing_Month = monthStr,
        Usage_Start_Date = startDate,
        Usage_End_Date = endDate,
        Number_of_Days = daysCount,
        Agreed_Rate = rate,
        Discount_Amount = ifNull(discount, 0.0),
        Taxable_Value = taxable,
        GST_Rate = 5.0,
        GST_Amount = gstAmt,
        Invoice_Value = invoiceVal,
        Billing_Status = "Pending Invoice",
        Billing_Notes = notes
    ];
    
    alert "SUCCESS: Fixed Monthly Rental Log " + newLog.Rental_Log_ID + 
          " generated for " + monthStr + " (Invoice Value: ₹" + invoiceVal + "). Ready for invoicing!";
}

     * Taxable_Value = (Number_of_Days * Agreed_Rate) - Discount_Amount
   - For Fixed Monthly Rental:
     * Taxable_Value = Agreed_Rate - Discount_Amount (Fixed flat monthly amount, independent of days)
   - GST (5%):
     * GST_Amount = Taxable_Value * 0.05
   - Total Invoice Value:
     * Invoice_Value = Taxable_Value + GST_Amount

3. Customers - Auto-Populate from Zoho Books (Form -> On User Input):

     Step 3: Count active bed stations in `Bed_Station` for `customerId`.
     Step 4: Update the corresponding counter fields on the `Customers` record.

6. Standalone Live Lot Recalculation Engine (Functional Blueprint in Plain English):
   - Trigger: Automatically invoked whenever any asset record in `Asset_Master` is created,
     updated, advances its `Manufacturing_Stage`, or receives a test verdict in `Quality_Control`.
   - Process Flow:
     Step 1: Identify the parent `Lot_Number` from the triggering asset.
     Step 2: Aggregate Control Units:
             - Count all CUs linked to this lot.
             - Count CUs where `Manufacturing_Stage == "CU-6: Manufacturing Complete"`.
             - Derive CUs in progress = Total CUs - Completed CUs.
     Step 3: Aggregate Overlays:
             - Count all Overlays linked to this lot.
             - Count Overlays where `Manufacturing_Stage == "OV-6: Manufacturing Complete"`.
             - Derive Overlays in progress = Total Overlays - Completed Overlays.
     Step 4: Sum Total Combined Units = Total CUs + Total Overlays.
     Step 5: Write updated totals to the `Lots` record atomically.

7. Manufacturing Stage-Gate Enforcement Engine (Functional Blueprint in Plain English):
   - Trigger: On Save of `Asset_Master` and On Validate of `Stock_Transfer_Items`.
   - Process Flow:
     Step 1: Check `Asset_Master.Manufacturing_Stage`:
             - If stage is in preliminary assembly (Stages 1 through 5), systematically lock `Operational_Status` = "In Manufacturing / Assembly" and `QC_Certification_Status` = "Pending QC".
             - Disallow assignment of asset to any physical dispatch transfer.
     Step 2: When stage is updated to Stage 6 ("Manufacturing Complete"):
             - Verify that a passed test record exists in `Quality_Control`.
             - If passed, transition `Operational_Status` to "Available in Stock" (Rent Ready) and `QC_Certification_Status` to "Passed & Certified".
             - If no passed test exists, transition `Operational_Status` to "Quarantine - Pending QC".

8. Agreement Auto-Naming & Mode-Based System Assignment Engine (Functional Blueprint):
   - Trigger 1: `Rental_Agreement` creation/edit.
     * `Agreement_Title` is automatically generated by concatenating `[Customer_Name] - [Item_Name]`.
     * Upon record creation, `[Rental_Agreement_ID]` is appended: `Customer Name - Item Name (RA-YYYY-XXXX)`.
     * Guarantees unambiguous lookups across all forms when a hospital operates multiple beds.
     * Legacy `Authorized_System_Quota` is eliminated in favor of active runtime validation.
   - Trigger 2: `Bed_Station` system assignment (On Validate).
     * If linked `Rental_Agreement.Rental_Mode` == "Pay Per Use (Daily)":
       - Any number of bed stations can be deployed under the same agreement.
       - Agreement start date does not constrain individual station deployment or daily billing.
     * If linked `Rental_Agreement.Rental_Mode` == "Fixed Monthly Rental":
       - Strictly validated: Only 1 active bed station (`Deployment_Status != "De-installed / Closed"`) is permitted.
       - If an active station is already attached, submission is blocked with an alert.
       - Station `Deployment_Start_Date` auto-initializes from `Agreement_Start_Date` to anchor recurring monthly billing.
   - Trigger 3: Live Active Counter Recalculation (On Success of `Bed_Station`).
     * Automatically queries active stations (`Deployment_Status == "Active on Patient Bed"`) and writes the live count to `Rental_Agreement.Active_Deployed_Stations`.
     * For Fixed Monthly: count is 0 (pending deployment) or 1 (active).
     * For Pay-Per-Use: count reflects the real-time active hospital fleet (e.g. 5, 8, 12).

6. ZOHO BOOKS ACCOUNTING & INVOICING INTEGRATION ARCHITECTURE
================================================================================

1. Customer Onboarding & Sync:
   - Zero-friction customer onboarding: User selects customer via Zoho Books Contact picker.
   - Deluge fetches Name, Classification (Business vs Individual), and Address automatically.
   - Creator Customers module locks synced fields against manual editing, ensuring accounting consistency.
   - Irrelevant operational fields like GSTIN and Phone Number are excluded from Creator form.
2. Branch Locations:
   - Locations in Creator mirrors the 3 GST registered offices (Bangalore HQ, Kerala Office/Palakkad, Nagpur Office).
   - The stored Location_ID is passed directly into Zoho Books Delivery Challan API calls (`location_id`), ensuring Challans and E-Way bills are issued under the correct branch GSTIN without virtual warehouses.
3. Product Catalog Sync:
   - Product_Catalog_Master in Creator <--- Service Items in Zoho Books (via Sync button).
   - Only active service items starting with "Rental" are synced.
   - Zero duplication: Each Zoho Books service item is 1 row in Creator with Item ID as Primary Key.
   - Automatically derives Rental Mode (Daily Pay-Per-Use vs Fixed Monthly) and Hardware Model.
4. Automated Books Invoice Push (Standalone & Consolidated Invoicing):
   When Accounts clicks "[ Push to Zoho Books ]" on an individual Rental Log, OR selects multiple logs on the report and clicks "[ Push Consolidated Invoice to Books ]":
   - Script generates a Draft Invoice in Zoho Books for Accounts review.
   - Line item description:
     "Patient Repositioning System Rental: [Product Model] | Bed Station: [Bed Label] | CU: [CU Serial], Mattress: [Overlay Serial] | Period: [Start] to [End] ([Days] days)"
   - Quantities & Rates:
     * Pay-Per-Use: Quantity = Number of Days, Unit Rate = Agreed Daily Rate.
     * Fixed Monthly: Quantity = 1, Unit Rate = Taxable Value (Agreed Monthly Rate - Discount).
   - Taxes: 5% GST automatically mapped.
   - The generated Zoho Books Invoice ID, Invoice Number, Invoice Date, and direct Invoice URL are updated on all linked Rental Log rows, and status flips to "Invoiced".
